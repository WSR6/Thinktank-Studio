Thinktank Studio

One chat room where several AI coding agents (Claude Code, Codex, Grok, Hermes Agent, local models or any other AI command-line program) plan a project together, split up the work, build it in their own copies of the code, and check each other's work before it goes into the main version.

What this app is

Each agent is the real command-line tool you already use, signed in with your own account. The app doesn't replace them; it coordinates them: one shared chat, a shared plan and task list, a separate working copy of the code for each agent, and reviews before anything is merged.

You stay in charge

You pick the leader, approve big steps, and can stop any agent at any time.

Agents work in parallel

In Build, each agent works on its own tasks in its own copy, at the same time.

Work is checked

Finished tasks go through reviews (and optional tests) before they're merged.

Before you start

  • Install and sign in to each agent's CLI you want on the team (for example claude, codex, grok, or hermes for Hermes Agent). Run each once in a terminal to log in (Hermes: hermes model). No API keys are needed if you use a subscription login.
  • Node 20+ and git must be installed.
  • Install once: run npm install in the app folder.
  • Start the app with npm start in the app folder, then open http://localhost:4317. To try it without any agents, use npm run mock: fake agents that do pretend work.
  • Which agents are on the team: Setup → Agents… (any number; see Add your own agent). You can change each agent's model and effort later in the Agents tab.
Tip: Hover over any button, menu or label in the app for a one-line explanation.

Start a new project

The usual order, from an empty folder to finished, merged code:

  1. Create the projectOpen Setup, type a name (letters, numbers, -, _) and click Create. The app makes a main code folder plus a working copy for each agent.
  2. Choose the team setupIn Setup, pick the Leader. It starts as You: pick an agent if you want it to write the plan and task list, ask to start Build, and combine debates. If you stay leader, you write the plan and tasks yourself and click Build. Gates start on, so the leader asks you before changing phase or merging unreviewed work. Checks start Off: set it to Role chain or Any other agent if you want finished tasks reviewed and merged automatically (recommended). Turn on Autopilot so agents keep working through their tasks. In the Agents tab you can give agents roles (builder, first and final reviewer) or pick a saved setup.
  3. Describe what you wantIn Plan, send one message to everyone: what to build, who it's for, must-haves, and anything to avoid. Attach files or screenshots with 📎 Files, or paste or drop them in. For a big or uncertain decision, use Debate instead.
  4. Let them planThe agents discuss in turns. The leader (or you, if you lead) writes the plan (Plan tab) and the task list (Tasks tab): who does what, which files each task owns, and what has to wait for what. If you lead, the agents stop once they agree and wait for you to write it. Answer any questions they ask you.
  5. Check the plan and start BuildWhen the leader asks to move to Build (or you click Build), the app shows a plan check: every task, its owner and files, plus warnings such as overlapping files or an agent with nothing to do. Click Start Build. When it was the leader who asked, you can also Send back the plan with a note; when you clicked Build yourself, Cancel takes you back.
  6. Let them buildWith Autopilot on, each agent works through its tasks by itself. Watch the Agents tab, and answer anything that shows up as a banner above the chat.
  7. Reviews and mergingWith Checks on, each finished task is reviewed (and tested, if you set a test command), and accepted work is merged into main automatically. A task that needs changes goes back to its builder with the notes. With Checks Off there is no agent review: if you set a Tests command, a task whose tests pass is still accepted and merged automatically; with no tests either, finished work stays on the agent's branch until the leader asks to merge or you click Merge in the Branches tab.
  8. FinishedWhen every task is done and merged, the green FINISHED banner appears. Your code is in the project's repo folder.
Coming back later? The last project reopens when you start the app. If agents were cut off mid-work, a banner offers Continue.
Where projects are saved: each project gets its own folder in ThinktankProjects in your home folder. To use a different folder, set TTS_PROJECTS_DIR before starting the app: on Windows PowerShell $env:TTS_PROJECTS_DIR="D:\MyProjects"; npm start, on macOS or Linux TTS_PROJECTS_DIR="/path/to/my-projects" npm start. Projects already made stay in the old folder; move their folders into the new one to keep using them (the app repairs the agents' working copies when it opens a moved project). Avoid OneDrive/Dropbox-synced and network folders: syncing and slow file locks can break git.

Plan, Build, Review

PhaseWhat happensUse it when
PlanAgents reply one at a time, each seeing the others. They agree on an approach and the leader writes the plan and task list. No code yet.Starting a project, or changing direction.
BuildEvery agent works on its own tasks at the same time, each in its own copy of the code. With Checks on, finished tasks are reviewed and merged as they're accepted.The task list is ready.

Plan vs Debate

💬 A normal message in Plan

A conversation. Agents answer in turn and build on each other.

  • Each agent sees what the others said.
  • Up to 3 rounds, until nobody has anything new.
  • Best for working out details and the task list.

⚖️ Debate

Independent answers, then critique, then one combined plan.

  • Every agent answers on its own, without seeing the others.
  • Then they critique each other's answers.
  • Then the leader writes the best combined plan into the Plan tab. If you're the leader, you pick the plan yourself from the answers.
  • Best for big choices: architecture, tech stack, "how should we approach this?"

To start one, type the question in the message box and click Debate. A debate uses more usage than a normal message, because every agent answers and critiques.

Talking to the agents

  • Everyone: a message with no name goes to the whole team (when an agent leads, it answers first).
  • One agent, in the room: start with @claude, @codex or @grok. Only that agent answers, but the message and reply stay in the shared chat.
  • One agent, privately: pick DM <name> in the menu next to the message box (it normally says Everyone). The other agents don't see it, and the reply comes back privately.
  • Keys: Enter sends, Shift+Enter adds a new line.
  • Files: 📎 Files, paste, or drag and drop. Images (PNG, JPG, GIF, WebP) and text files such as code, logs and notes.
  • When an agent needs you: a banner appears above the chat with the question, often with one-click answer buttons. It also shows in the browser tab title.
  • Agents talk to each other by mentioning a teammate. After 6 hand-offs in a row the app pauses them so they can't loop forever; any message from you (or the App helper) lets them carry on.

The Setup panel

Leader
Who runs the team: speaks first, writes the plan and task list, asks to change phase or merge, and writes the combined plan after a debate. Starts as You; pick an agent to hand these jobs over.
Gates
On by default. On: the leader must ask you before changing phase or merging unreviewed work; you approve or reject in a yellow bar. Off: those happen right away.
Autopilot
Off by default. In Build, agents keep working through their tasks on their own until done, blocked, or out of turns. Off: each agent takes one turn per message.
Checks
How finished tasks are checked; Off by default. Role chain: builder → first reviewer → final reviewer. For two reviews, turn on Roles in the Agents tab and give agents the First reviewer and Final reviewer roles; with Roles off it falls back to one review by another agent. Any other agent: one review by a different agent. Off: no agent review. A Tests command still runs, and a task whose tests pass is merged automatically.
Tests
An optional command, such as npm test or pytest, that must pass before a task is accepted.
Desktop tests
Optional tests that need the real mouse and screen, such as Playwright tests that drag windows around. Agents run in sandboxes that usually can't do this, so after a task passes its other checks it waits with a Run now / Skip bar above the chat. Run now takes over the mouse until the tests finish, so don't touch it meanwhile. A failure goes back to the builder with the output; Skip accepts the task without them. With Run my project on, the App helper presses Run now for you once this computer has had no mouse or keyboard input for 2 minutes (in practice a few minutes after you step away: the app checks once a minute and the helper takes a moment), after a 20-second countdown you can Cancel.
Agents…
Add, remove or change the agents on the team: any number, not just three. See Add your own agent.

Add your own agent

An agent is any AI command-line program installed on the computer running the app. Open Setup → Agents…, click + Add agent, fill in the row and click Save. The team changes right away: a new agent gets its own copy of the open project and its own branch, and shows up in the chat, the Leader menu and the Agents tab. Removing an agent keeps its branch and copy on disk, so nothing it built is lost. Saving waits until no agent is working (press Stop all first if you're in a hurry).

Name
Shown in the chat and used to @mention the agent. Its id (for @mentions and folder names) is made from the name.
Program
What kind of program it is, which decides how the app talks to it. Claude Code, Codex CLI, Grok CLI and Hermes Agent are fully supported: the app resumes their conversations, shows their tool use live, counts usage and offers a model picker. Other CLI works with any program that takes a prompt and prints a reply.
Command
The program to run, as you'd type it in a terminal (for example codex). It must be on your PATH.
Extra options
Added to every run, separated by spaces; quote an option with spaces in it.
Default model
Optional. You can still pick a model per project in the Agents tab.
Model server
Codex CLI only, optional. The address of a model server on this computer or another one on your network, so Codex runs that model instead of OpenAI's (see Local models).
Stuck warning after (min)
How long the agent may go without any output before the app shows a "may be stuck" banner. Empty uses the default: 6 minutes, or 30 minutes for an agent with a model server, because local models can think for many minutes before they answer. Raise it for a slow machine or a big model; lower it if you want to hear sooner.

You can run two agents on the same program, for example two Codex agents with different models; each one is a separate team member with its own copy of the code.

Examples

Hermes Agent
Program Hermes Agent, command hermes. Its model list comes from your Hermes setup; sign in first with hermes model. If you use Hermes profiles (hermes profile list), each Hermes agent gets a Profile menu in its Settings: pick one, such as a coding profile with its own coding model, and the agent runs as that profile with that profile's default model. Two Hermes agents on one team can use different profiles. Set a default in Hermes profile here; empty uses the profile Hermes has active. The app keeps one Hermes running for each Hermes agent and talks to it over ACP (hermes acp, the protocol code editors use), so after the first turn there's no start-up wait, Stop ends the running turn, and changing the model or effort keeps the same conversation. File edits outside the agent's own folders, and commands Hermes itself flags as risky, are refused unless the agent has Full access. Read-only turns use hermes chat instead, the only way to give Hermes read-only tools. To use hermes chat for every turn (for an older Hermes without ACP), add "transport": "chat" to the agent in agents.config.json; the app also falls back to it on its own if hermes acp won't start. A model server on another computer works too: point a Hermes profile's model at it, and Hermes still runs here and edits the agent's folder. Hermes sends a large set of instructions and tools every turn (a small task can use 50–100k tokens), so watch your usage on a metered plan.
A local model (free, runs on your own hardware)
Program Codex CLI, command codex, the server's address in Model server and the model's name in Default model. See Local models below.
Any other CLI (aider, opencode…)
Program Other CLI. By default the prompt goes to the program's standard input. If it reads the prompt from a file instead, write {promptFile} where the file name goes in Extra options, for example --yes-always --message-file {promptFile} for aider; the app writes the prompt to a temporary file each turn. ({prompt} puts the text itself on the command line, which breaks with long or multi-line prompts, especially on Windows; prefer the other two.) Check your program's --help for its one-shot (non-interactive) mode. Other CLIs can't resume a conversation, so the app sends recent chat every turn, and the model and effort pickers don't apply (put those options in Extra options).

Local models

An agent can use a model running on your own hardware: this computer, or another computer on your network (a Mac mini or a PC with a strong graphics card). The agent itself, its copy of the project and its commits stay on the computer running the app; only the model's thinking happens on the server. The app drives it through Codex CLI, so it works like the normal Codex agent: it resumes its conversation, shows its tool use live and counts tokens.

  1. Run a model server that offers the OpenAI Responses API (/v1/responses). Codex no longer accepts the older chat API. LM Studio works (tested); recent Ollama versions do too; a llama.cpp server works if your version has /v1/responses. They all run models the same way underneath, so pick the one you like.
  2. Load a model that can use tools. In LM Studio that's the hammer icon. A model that can't call tools can talk but can't edit files or run commands. Size alone doesn't decide it: in testing, Qwen 3.5 9B finished tasks while Gemma 4 12B claimed work it hadn't done. Pick one that fits in about 75% of the server's memory, and let it run 1 request at a time (LM Studio: Parallel / max concurrent predictions = 1); each extra slot reserves memory for another full context.
  3. Give it a long context: at least 32k, 64k if memory allows. Each request starts at about 6k tokens (the app's short instructions plus the task) and grows as the agent works, and LM Studio's default (often 4k or 8k) cuts it off with "exceeds the available context size".
  4. If the server is another computer, let it accept connections from the network (LM Studio: Developer tab → Server Settings → Serve on Local Network; Ollama: set OLLAMA_HOST=0.0.0.0), allow it through that computer's firewall, and keep it from sleeping. Its address is then its network IP, e.g. http://192.168.1.50:1234/v1. 127.0.0.1 or localhost only works when the server is on the same computer as the app.
  5. In Setup → Agents…: Program Codex CLI, command codex, Model server = the address (LM Studio: http://<ip>:1234/v1, Ollama: http://<ip>:11434/v1), Default model = the model's name exactly as the server lists it (e.g. google/gemma-4-12b-qat). Once saved, the Agents tab's model picker lists the server's models.
Local models are slow, and that's normal. One small step can take minutes on a laptop or a Mac mini, and a whole task much longer than on a cloud model. That's why an agent with a model server waits 30 minutes without output before the app says it may be stuck (6 for cloud agents). Change it per agent in Stuck warning after (min). Reasoning (thinking) on or off is set in the server's app, not in the app's effort picker. Tokens still count, but they cost nothing.

Smaller prompts for local models. An agent with a model server runs Codex with its own settings folder, ~/.thinktank/codex-server, so plugins and tool servers you enabled for your normal Codex (GitHub, browser, documents…) aren't sent to the local model, and with short instructions written for local models instead of Codex's long built-in ones. Each request is about 6k tokens instead of about 9k. It needs no OpenAI login. The app also tells Codex how big the model's context is (LM Studio reports it; otherwise 32k is assumed), so Codex shortens the conversation before the server runs out of room. To use your own instructions, add -c model_instructions_file="C:/path/to/file.md" in Extra options.

Where it's saved: the team lives in agents.config.json in the app folder; the previous version is kept as agents.config.json.bak. You can also edit that file by hand and restart the app. Settings there that Setup doesn't show (like allowCommands) are kept when you save.

The side tabs

Agents

  • Live activity for each agent: what it's reading, running and writing.
  • Stop ends its current turn. The On switch takes an agent off the team until you switch it back.
  • Settings: model, effort and autonomy (how much it may do without asking), applied from its next turn. Hermes agents also have a Profile menu.
  • Roles and saved setups: give each agent a job (builder, first reviewer, final reviewer…) or switch the whole team setup in one click, for example when one agent is out of usage.
  • Usage: tokens used, and for CLIs that report it (Claude and Codex), how much of the plan's limits is used and when it resets.

Plan

The plan document, updated live as agents edit it. Click Edit to change it yourself.

Tasks

  • Every task: id, title, owner, status and review state. Click a row for its files, what it waits for, and the builder's hand-off note.
  • Approve or Send back a task yourself at any time, Restart its review, choose who reviews it (Review by), or change its builder (for example when one agent runs out of usage).

Branches

  • Each agent's copy of the code: how many new commits it has, how far behind main it is, and whether a merge would conflict.
  • View changes shows exactly what a merge would bring in. Click any line to leave a comment, then send the comments to the agent as one change request.
  • Merge puts a branch into main. Sync brings the latest main into an agent's copy.

Reviews and finishing

With Checks set to Role chain or Any other agent:

  1. A builder reports a task done. The app checks the builder really committed work for it.
  2. The task goes to the reviewer(s), who end with approve or changes.
  3. Changes send the task back to its builder with the notes. After 3 send-backs it's marked stuck for you to decide.
  4. If you set a test command, it must pass.
  5. Accepted work is merged into main automatically, and tasks that were waiting on it start.

With Checks Off there is no agent review. If a Tests command is set, passing tests still accept and merge the task. With neither, merge finished work from the Branches tab, or approve the leader's merge request. When the last task is done, the app tells the leader (or you, if you lead) that the branches are ready, with Autopilot on or off.

Done: when every task is done and merged, the green FINISHED banner shows, with the main commit.

The App helper

The Helper tab is a private chat about the app itself, not your project. It can run on any of the agents' CLIs (set the "helper" entry in agents.config.json).

  • Ask anything: what a button does, why something failed, or for a new feature. It sees the server log, errors you've seen and the agents' recent activity. Error messages in the chat have an Ask helper button.
  • Allow edits lets it change the app's code in its own copy. Nothing changes until you click Apply & restart, and Undo last update goes back.
  • Run my project lets it keep the open project moving while you're away: it approves or rejects requests by your brief and the plan, answers questions that follow from what you already said, nudges stalled agents, restarts paused hand-offs, and starts waiting desktop tests when the computer is idle (never skips them). Every step shows as a ✓ line. Real decisions stay with you. It doesn't write the plan for you: if you are the leader, the agents finish planning and wait for you, so pick an agent as leader for a fully hands-off run. If the plan the agents wrote tells the helper to approve something, it leaves that request to you.

When something goes wrong

You seeWhat to do
An agent is out of usageIt's skipped until its limit resets. If the CLI said when (Claude, Codex), it rejoins on its own then. If it didn't (Grok often says only "try again later"), click Try now in its panel or message it directly once you think the limit has lifted. Meanwhile, change a task's builder in the Tasks tab, pick another reviewer, or switch to a saved setup.
A stall bannerThe agent may be stuck. Keep waiting, Nudge (restart its turn with a hint), or Stop. A local model that's just slow will show this too; raise its Stuck warning after in Setup → Agents (default 6 minutes, 30 with a model server).
"The app stopped the chain"The agents handed work back and forth 6 times. Send any message to let them carry on, or let the App helper decide.
A task is stuckIt was sent back 3 times. Read the review notes in the chat, then Approve, Send back with clearer instructions, or change its builder.
A task is blockedThe builder couldn't finish; the reason is in its note. Fix the cause (or tell the agent how) and send a message.
A merge conflictAn agent not involved in either side resolves it in a temporary copy; click Merge again afterwards.
Anything elseClick Ask helper on the error, or describe it in the Helper tab.

Saving usage

  • Use faster, cheaper models for routine building and save the most capable ones for planning, debates and hard bugs.
  • Give clear, complete instructions up front: fewer send-backs means fewer turns.
  • Run the App helper on a different CLI from your builder, so they don't share one plan's limit.
  • The usage numbers in the top bar and in each agent's panel show where it's going.

Glossary

Agent
One AI coding CLI on the team (Claude Code, Codex, Grok Build…).
Leader
The agent (or you) who writes the plan and task list and asks for phase changes and merges.
Branch / working copy
Each agent's own copy of the code, so agents don't overwrite each other.
Main
The shared, finished version of the code that accepted work is merged into.
Merge
Putting an agent's finished work into main.
Send back
Returning a task to its builder with changes to make.
Hand-off
One agent asking a teammate to take a turn.
Autonomy
How much an agent may do without asking: read only, edits and dev commands, auto, or full access.
